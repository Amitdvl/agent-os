# Migration Guide

## New Mac or new user

1. Clone the private repository.
2. Run validation and a safe setup preview.
3. Choose profile, packs, and hosts.
4. Apply portable instructions and skills.
5. Install selected external tools from reviewed sources.
6. Create the new machine's encrypted vault inventory.
7. Authenticate selected services manually.
8. Grant macOS permissions deliberately.
9. Run status and doctor; resolve only desired optional capabilities.

## What never migrates through Git

- encrypted vault records or decrypted values;
- API keys, OAuth material, cookies, sessions, browser profiles, or keychain data;
- message/social/Notion archives and private databases;
- Obsidian vault contents;
- recordings, call logs, phone numbers, account/workspace IDs;
- Codex/Claude sessions, logs, memories, caches, runtime state, or plugin caches;
- absolute paths from the old Mac.

## Existing instruction files

Agent OS appends or updates only its delimited block. Review the preview when the new user already has global instructions. Existing command/skill files at managed destinations are conflicts and are never silently overwritten.

## Amit parity

Parity means the same portable decisions, commands, packs, routing, safety, freshness, focus, and verification model. It does not mean copying account authority or private data. Platform/host-specific features may require equivalent adapters rather than byte-identical files.
