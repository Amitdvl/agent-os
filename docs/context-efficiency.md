# Context efficiency

Keep shared safeguards and concise capability routing in global instructions.
Before tool use, load its managed SKILL.md and declared routing.md. Detailed
recipes live in templates/local-tools/routing and are deployed into managed tool
folders; the installer renders routes using the configured localToolsRoot and
registry.json, including custom state directories. Missing required references
must be resolved before operating the tool.

The live migration preserved the former per-tool recipe text in each local
routing.md. Portable copies replace machine paths with configuration placeholders.
AgentInbox and Vox recipes remain machine-only under the existing inventory
exclusions. Existing tool skills, symlinks, binaries and configuration stay intact.

Bound output at its source: selected fields, relevant excerpts and pagination.
Retain full noisy build/test logs locally, preserve real exit codes, and expose
failures. Requested complete content and tool-specific verbatim output contracts
take precedence over default output budgets. Never truncate required instructions.

This changes guidance, not model choice, reasoning effort, memory settings,
skill-catalog budgets or the global tool-output limit. Smaller prompts are
measurable; quota savings depend on caching and workload and are not guaranteed.
