# Standing instruction consolidation

One generated profile block owns portable behavior. The private wrapper contains
only owner tone, local hook/checkout/vault/registry/helper bindings and narrow
owner-granted UI setup authority. It is never exported. Profiles continue to
select the same eight policy sources; policy markers and ownership stay intact.
Word count is descriptive, never an acceptance criterion.

## Contract-root reconciliation

Canonical tool entry points require their detailed sibling routing file. Portable
routing combines useful old machine contract behavior with generated setup,
privacy, authentication and source-plan boundaries. Private defaults and helpers
stay local. Retired document paths may alias canonical documents after backups;
never replace whole directories that also contain executables or source.

Resolve old contradictions by existing effective authority: YouTube is fully
allowed (the obsolete timed-allowance note is superseded); Spotify remains
blocked despite obsolete login suggestions. Supported archive content reads are
allowed within task scope; credential/session stores and state migration remain
forbidden. Sync is a local freshness operation with side effects, not a promise
of a side-effect-free read.

## Verification limits

Independent scenario guards derive from the pre-cleanup requirements. Negative
removal/drift challenges check that missing safeguards are detected; actual CLI
renders check all profiles, wrapper preservation and contract deployment. Twin
audit checks exact managed policies, routing and canonical roots. These checks
protect instruction content and wiring; they do not guarantee that every future
model invocation will follow every instruction. Preserve uncertain behavior
rather than treating text compression as proof of equivalence.
