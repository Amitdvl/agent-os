# Silicon routing requirements

- Silicon: use `silicon` when the user asks Codex to create, send, or share a code screenshot or code image. Run `command -v silicon`, `silicon --version`, and `silicon --help` before relying on it in a new task. Treat source and rendered pixels as private: inspect the exact bounded snippet for secrets, extract requested line ranges before rendering because `--highlight-lines` does not crop, use isolated trusted config/cache paths, neutral titles, and an explicit new PNG destination. Avoid clipboard modes, custom themes/fonts/backgrounds, cache builds, and overwrites unless explicitly requested. Silicon can print an error while exiting zero, so verify the PNG exists, is nonempty, has the expected file type, and visually contains only the intended code before presenting or sending it. Rendering does not authorize external sharing; require the exact destination and content under the destination tool's rules, and include copyable fenced code when useful.
