# NoteBridge discovery, inspection and guarded changes

Use NoteBridge for local Apple Notes, read-only Wispr reads, explicit exports, guarded Apple changes and one-way mirroring. Verify installed version/help and sanitized doctor capabilities/build identity first. Use the registered binary path if a noninteractive shell omits it.

- Choose `--source apple` or configured `NOTEBRIDGE_SOURCE`. Discovery is compact/paginated; Apple search defaults to titles. `--scope body|all` searches current bodies without an index; `--full` retains legacy complete records/title-body matching. Native inventory may include Recently Deleted: filter a folder for active-only results.
- Fetch selected stable IDs through get/batch-get and bound `--fields`; use rich/structured views for formatting evidence. Original HTML requires explicit `--include-raw`. Preserve multilingual content, whitespace, links and discarded-text markers; never use normalized text as a rich-body replacement.
- Keep note/image/private URL content within task scope. Image/attachment inspection requires an explicit output path and stable attachment ID or embedded image index. Report unmapped/unexportable attachments and unknown metadata honestly; header recognition alone does not prove image validity. There is no remote image download or Notes network sync.
- Apple create/update/append/replace/move/delete need exact action and stable target or creation destination. Preview real inputs, differences, consequences and expected hash, then apply using `--if-match HASH --apply --yes`. Stale state refuses before dispatch. Prefer formatting-preserving append or exact one-text-node replacement.
- New image references, existing attachments and ambiguous native list/table edits fail closed. Title-only edits retain the body; native rename changes name metadata while preserving the original first body heading. Whole-body HTML edits require explicit raw retrieval, preserving the title and reviewing actual consequences.
- Read back exposed title/content, original-content prefix and intended change. Delete readback can report disappearance or native destination transition. Native checklist completion/history, atomic CAS and rollback are unavailable; do not claim stronger guarantees. Never test writes on existing user notes; use authorized disposable fixtures.
- Mirrors need exact account/folder and reviewed dry run; they are one-way, conflict-aware and never delete Notes. Exports require destinations; overwrite needs explicit force authority. Wispr remains read-only. No credentials or network client are needed.
