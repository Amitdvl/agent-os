# Pre-Publication

Usage: `/pre-publication [project reference]`. A reference may be a path, GitHub URL, repository name, or an unambiguous project name; it is optional whenever the intended repository is clear from context. `<project>` is illustrative syntax, not a literal requirement. Also respond to the explicit `$pre-publication` skill invocation on Codex hosts that do not support custom slash-command UI entries. A uniquely resolved project plus this command authorizes the ordinary preparation and public GitHub launch, without a second routine publish confirmation. It does not authorize publishing a different repository, exposing private content, or rewriting shared history.

Read the `publication-safety` skill and use its bundled guard. Resolve the intended project from the user's wording and available context: consider an explicitly named path or repository first, then the current/selected Git workspace, recent task context, and a unique authenticated GitHub repository match. Do not ask for a project reference merely because the command omitted one; proceed when those signals identify one safe candidate. Ask only when there are multiple plausible repositories or no reliable candidate. Identify the GitHub owner/repository from a verified remote or resolved unique match. If the destination, public rights/license choice, or intended disclosures cannot be established, stop for that specific decision.

1. Inspect the repository, instructions, Git and GitHub state. Run the full publication-safety audit, including historical refs, untracked/ignored material, public metadata/artifacts, and an independent history-capable secret scanner. Classify findings without showing secret values.
2. Make safe, scoped local repairs; add and verify layered future-commit guards. Run project tests. For history findings, revoke/rotate real secrets and stop for coordinated history remediation if needed. Never turn a finding into an unreviewed allowlist exception.
3. Before any external change, verify authenticated control of the exact GitHub destination and the complete publication set (branches, tags, LFS, releases, forks, issues, wiki, Actions history/logs). If remote history or settings cannot be inspected, stop. Do not use `--no-verify`, force-push, delete the original repository, or treat a new clean clone as a substitute for handling the old private remote without an explicit choice.
4. Commit only intended preparation changes. On that frozen candidate SHA, invoke the official `codex-security:security-scan` Standard repository scan, read its completed report, triage and resolve relevant findings, and run the bundled guard plus independent history scanner again. A scanner launch, unfinished scan, inaccessible report, or a report for a different SHA is not a passing result. Repeat this gate after any candidate change. The Codex Security scan covers code security, not all credentials, history, LFS payloads, or public metadata; all other audit gates still apply.
5. Push only inspected refs. If creating a repository, use the resolved owner/name and private visibility first; verify pushed state and safety controls before changing it to public. For an existing private GitHub repository, inspect its remote history and public-facing surfaces before changing visibility. Immediately re-read GitHub visibility, default branch, and safety controls afterward. If GitHub disables a push rule during the visibility change, restore/verify the intended rule before claiming future protection.

Stop with a concise blocker when either required scanner is unavailable or incomplete, a private datum is unresolved, an existing public surface cannot be inspected, authority/target is ambiguous, an irreversible remediation needs a choice, or verification fails. Treat repo-owned CI and clone-local hooks as advisory until effective trusted remote rules and each active worktree are verified. Report the target and URL only after verifying the repository is public; otherwise say exactly what was prepared and what remains blocked. Never claim that any guard makes leaks impossible.
