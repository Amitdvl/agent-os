# Bounded delegation

Delegate only when the main skill's activation or testing-ownership rule applies.
Separate roles improve evidence only when their boundaries are real.

An assignment includes the outcome, source state, relevant paths, allowed writes,
non-goals, acceptance checks and required evidence. Pass the relevant skill or
reference explicitly; never assume inherited context. Ask a reviewer for a
judgment against requirements without telling them the desired conclusion.

Keep one writer per mutable file or system. Sequence dependent tasks; use isolated
checkouts for independent changes when needed. A worker may report an ambiguity or
probable defect, but cannot expand the goal, acquire authority or silently hand
its scope to another worker.

Use fresh reviewers when independence matters. Distinguish two questions:

- Does the result meet the user's requirements without unwanted additions?
- Is the implementation maintainable and verified at its real boundaries?

One reviewer may answer both for a small change. Do not mandate two review agents
or one implementation agent per tiny task. The lead inspects the diff, reconciles
findings, reruns integrated checks and owns the final completion decision. Worker
claims, test totals and green summaries are inputs, not acceptance evidence.
