# Tool Routing

Use the selected pack manifests to choose an installed upstream CLI. Run a lightweight interface check when exact support matters. Prefer structured bounded reads, apply declared freshness rules, and require exact intent for writes. Never treat a binary's presence as authentication, inspect its private state, or improvise an alternate browser path that violates the selected profile.

Read the selected registry entry's `SKILL.md` and sibling `routing.md` before
operation. Its declared skill and installed discovery symlink must resolve to
the same canonical contract; resolve missing references or competing roots
before acting. A legacy tool directory may still own executable helpers,
source, configuration or supplemental documentation: preserve those assets.

For adding, installing or standardizing a CLI, load `/add` and complete its
onboarding contract. Update the canonical contract pair, registry, discovery
symlink and capability catalog, plus the portable tool/source/secret manifests,
pack selection, generated allow rules, documentation and tests. Machine-only
items need an explicit inventory exclusion. Add a broad allow prefix for the
binary in the configured local rules, rather than one subcommand. Keep private
defaults in local configuration; do not copy archives, credentials, sessions or
machine-specific paths into portable source. Verify the installed interface,
both contract paths, twin audit and HUD entry before completion.
